# Contributing

Contributions are welcome through GitHub pull requests.

1. Open a non-sensitive issue describing the problem or proposed behavior.
2. Create a focused branch and include tests for behavior changes.
3. Run the encoding check, repository validation, and relevant Pester tests.
4. Submit a pull request that explains the user-visible change and validation performed.

Never include credentials, setup keys, personal paths, machine names, private logs, generated installers, or release archives. Report sensitive problems through the private vulnerability route in [SECURITY.md](SECURITY.md).

All contributors agree that their contributions are licensed under the repository's MIT License. Third-party code must retain its original license and attribution.

## Release roles

The project owner initially performs three documented roles: **author**, **reviewer**, and signing **approver**. Each release records which revision was reviewed and approved. These roles can be separated when additional maintainers join. Accounts with repository administration, workflow approval, or SignPath release duties must use multi-factor authentication (MFA).
