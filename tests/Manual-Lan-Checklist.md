# รายการทดสอบจริงบน Windows สองเครื่องหรือ VM

ยังไม่ได้รันรายการนี้บน LAN สองเครื่อง ห้ามถือว่าผ่านจากผล Pester เพียงอย่างเดียว

## ตัวติดตั้ง EXE และการเริ่มจากศูนย์

- [ ] รัน `LanFileSharing-Setup-v3.70.exe` ที่คัดลอกลงเครื่องผู้แชร์และเครื่องผู้ใช้ ตรวจว่าตัวติดตั้งเดียวกันมีทั้งสองแท็บ และไม่มี `Setup-Host.cmd`/`Setup-Client.cmd` ที่ต้องใช้
- [ ] ตรวจไอคอน Tiger Tech ที่ไฟล์ EXE ตัวติดตั้ง หน้า Setup ตัวเปิดโปรแกรม ทางลัด Start Menu หน้าต่างโปรแกรม System tray และรายการ Installed Apps
- [ ] ในแท็บผู้แชร์ เลือก `C:\Users\Teacher\Downloads` ขณะชนิดเป็น Drive ตรวจว่าโปรแกรมเปลี่ยนเป็น Folder ก่อนเริ่มแชร์และแถวใหม่แสดง Folder; เลือก `C:\` ตรวจว่ายังคงเป็น Drive
- [ ] ปฏิเสธ UAC หนึ่งครั้งก่อนติดตั้ง ตรวจว่าแชร์เดิม, Host Worker, Map Drive และการตั้งค่าเดิมยังอยู่ครบ
- [ ] เลือก Clean reset แล้วตรวจรายการแชร์/พาธเดิมในหน้าต่างยืนยัน ก่อนกด Yes ตรวจว่าต้นฉบับ Drive/Folder/File ไม่ถูกลบ
- [ ] ตรวจว่า Map Drive ที่โปรแกรมสร้างถูกลบเฉพาะบัญชี Windows ปัจจุบัน ส่วนไดรฟ์ที่ Map ด้วยวิธีอื่นยังอยู่
- [ ] ติดตั้งค่าเริ่มต้นบน Windows 64 บิตไปที่ `C:\Program Files\LanFileSharing`; ทดสอบ Windows 32 บิตแยกไปที่ `C:\Program Files (x86)\LanFileSharing`
- [ ] หลังติดตั้ง ตรวจ **Settings > Apps > Installed apps** ว่ามี LAN File Sharing และกด Uninstall จากตรงนั้น; ต้องเห็นรายการแชร์/Map Drive ของบัญชีปัจจุบันก่อนยืนยัน แล้วถอนการติดตั้งได้แม้ EXE อยู่ในโฟลเดอร์ที่จะถูกลบ
- [ ] จำลองการติดตั้งล้มเหลวระหว่างตั้ง Host Worker ในตำแหน่งที่เลือกเอง แล้วรัน Setup อีกครั้ง; ตัวติดตั้งต้องยังหาตำแหน่งเดิมเพื่อเก็บกวาด/ซ่อมได้
- [ ] **กันถอยหลังของ `manual recovery`**: แชร์ไดรฟ์ข้อมูลทั้งลูก (เช่น `F:\`) แล้วลบโฟลเดอร์ย่อยที่ถูกบันทึก ACL ไปหนึ่งโฟลเดอร์ จากนั้นกด Set zero หรือถอนติดตั้ง; ต้องไม่ขึ้น `interrupted setup still needs manual recovery` และต้องไม่มี ACL record ของ `$RECYCLE.BIN`/`System Volume Information` ถูกบันทึกไว้ตั้งแต่แรก
- [ ] เมื่อการล้างล้มเหลวจริง ต้องยังเห็น Scheduled Task ของ Host Broker/Worker อยู่ และมีข้อความบอกชื่อแชร์ เฟส และเหตุผลของรายการค้าง เพื่อกดซ้ำได้
- [ ] ที่เครื่องซึ่งเคยใช้ Guest ฝั่งผู้ใช้โดยยังไม่เคยแชร์จากเครื่องนั้น ล้างค่า Set zero แล้วตรวจว่านโยบาย Guest และ snapshot ของโปรแกรมถูกคืนค่า
- [ ] เลือกตำแหน่งติดตั้งอื่นบน NTFS ที่ป้องกันการแก้ไขโดยผู้ใช้ทั่วไป แล้วตรวจว่า Host Worker ใช้พาธใหม่นั้น; พาธที่ผู้ใช้ทั่วไปเขียนได้หรือเป็น junction ต้องถูกปฏิเสธ
- [ ] เปิดโปรแกรมใหม่ ตรวจสองแท็บและ Map Drive ที่เห็นใน File Explorer บัญชีปกติ โดยไม่ต้องเปิดโปรแกรมแบบ Administrator
- [ ] เปิด Start with the host แล้วลงชื่อออก/เข้าใหม่ ตรวจว่าโปรแกรมเปิดครั้งเดียว; เปิด Start minimized แล้วตรวจว่าเปิดใน tray เฉพาะตอนเข้าระบบ แต่การดับเบิลคลิกเปิดเองเรียกหน้าต่างกลับมา
- [ ] รีบูตโดยไม่ล็อกอิน ตรวจว่าแชร์ที่เลือก AutoStart กลับมาแล้ว แม้ Start with the host จะปิดอยู่

## ก่อนติดตั้ง

- [ ] บันทึกสถานะ Network profile, Network discovery, File and printer sharing, Public folder sharing, Password protected sharing และ 128-bit encryption ทั้ง Private/Public
- [ ] ติดตั้งบนเครื่องผู้แชร์ แล้วตรวจว่าไม่มี SMB share ใหม่และค่าข้างต้นไม่เปลี่ยน
- [ ] ตรวจว่า Scheduled Task ทำงานทันทีหลังติดตั้ง แม้ยังไม่มีแชร์ และโฟลเดอร์ติดตั้ง/ข้อมูลมีเจ้าของและ ACL เป็น Administrators/SYSTEM

## ผู้แชร์

- [ ] บน Private network แชร์ Drive แบบ Read; เปิดโฟลเดอร์ย่อยและไฟล์จากอีกเครื่องได้ แต่สร้าง/แก้/ลบ/เปลี่ยนชื่อไม่ได้
- [ ] แชร์ Drive ที่มี `System Volume Information` และ `$RECYCLE.BIN`; เริ่มแชร์ได้ โฟลเดอร์ระบบไม่ถูกเปลี่ยน ACL และผู้ใช้ทั่วไปเข้าโฟลเดอร์ระบบไม่ได้
- [ ] แชร์ Drive แบบ Modify ด้วย WindowsCurrent เมื่อมีโฟลเดอร์ย่อยที่เก็บ Deny SID ของบัญชีที่ถูกลบไปแล้ว; โปรแกรมสร้าง SMB share ให้ Authenticated Users ได้และไม่ลบ Deny เดิม
- [ ] เปิด GUI ที่ติดตั้งใหม่; ข้อความทั้ง 4 ช่องและค่าที่เลือกต้องไม่ทับกัน รวมทั้งเมื่อใช้การปรับขนาดข้อความของ Windows
- [ ] แชร์ Folder แบบ Modify; สร้าง แก้ ลบ และเปลี่ยนชื่อในโฟลเดอร์ย่อยได้
- [ ] เลือกไฟล์เดียว; ผู้ใช้เห็นเฉพาะไฟล์ที่เลือกในสภาพนิ่ง แก้ในที่เดิมแล้วต้นฉบับเปลี่ยนทันที
- [ ] บันทึกไฟล์เดียวด้วยโปรแกรมที่เขียนไฟล์ใหม่แทนที่ชื่อเดิม; ตรวจว่าต้นฉบับซิงก์กลับ และตรวจกรณีแก้ชนกัน
- [ ] เมนูวิธีเข้าใช้ทั้งสองโหมดเรียง WindowsCurrent, Protected Password, Guest โดย WindowsCurrent เป็นค่าเริ่มต้น; รายการแชร์ Protected เดิมยังแสดงและกลับมาหลังบูต
- [ ] แชร์ด้วย Protected Password แบบโปรแกรมสุ่ม; ตรวจว่ารหัสที่เห็นก่อนกดเริ่มแชร์ตรงกับรหัสที่ใช้เข้าแชร์ และปุ่มสุ่มใหม่ทำงาน
- [ ] แชร์ด้วย Protected Password แบบกำหนดเอง; ช่องรหัสซ่อนตัวอักษร ปฏิเสธค่าว่างและรหัสที่ Windows ไม่ยอมรับ ใช้รหัสที่กำหนดเข้าแชร์ได้ และปฏิเสธรหัสผิด
- [ ] แชร์ด้วย WindowsCurrent; ตรวจว่าไม่ถูกบังคับกรอกรหัสผ่านในโปรแกรมและไม่ตกไปเป็น Guest
- [ ] เว้นช่องบัญชีที่อนุญาตว่างแล้วสร้างแชร์ใหม่; ตรวจ SMB และ NTFS ให้ Authenticated Users ตาม Read/Modify และตรวจว่า Guest ยังไม่ได้สิทธิ์จากโหมดนี้
- [ ] ตรวจ Guest compatibility ทั้งสองเครื่อง; เมื่อ Windows บล็อก ต้องเห็นเหตุผลชัดเจนโดยไม่ลด SMB signing อัตโนมัติ
- [ ] ตั้ง Password protected sharing = Off บน Host ด้วยตนเอง แล้วเปิด Guest ผ่านปุ่มแยก; Client ต้องเข้าได้โดยไม่มีบัญชี/รหัสผ่านและแสดง SMB session เป็น Guest จริง
- [ ] คืนค่า Guest บน Client และถอนการติดตั้งบน Host; ตรวจว่าบัญชี Guest/นโยบายที่โปรแกรมเปลี่ยนกลับเป็นค่าเดิม
- [ ] กดเริ่มแชร์บน LAN ที่เป็น Public; โปรแกรมเปลี่ยนเฉพาะวงนั้นเป็น Private และเปิดแชร์ได้ โดยกฎไฟร์วอลล์ Public ไม่ถูกเปิด
- [ ] เมื่อมีหลายเครือข่ายพร้อมกัน โปรแกรมไม่เลือกเปลี่ยนวงใดเองโดยเดา
- [ ] โฟลเดอร์ที่มี junction/symlink และชื่อแชร์ชนกันต้องถูกปฏิเสธโดยไม่เปิดข้อมูลผิดขอบเขต

## ผู้ใช้ไฟล์

- [ ] เปิด UNC ผ่าน Explorer และอ่าน/เขียนตามสิทธิ์จริง
- [ ] ให้ Host Worker หายไปแต่เก็บการติดตั้งเดิมไว้; เมื่อเปิดแท็บผู้แชร์ โปรแกรมลงทะเบียนงาน SYSTEM ใหม่จากโฟลเดอร์ติดตั้งที่บันทึกไว้ แล้วรายการ AutoStart กลับมา
- [ ] เมื่อเครื่องผู้แชร์ไม่มีแชร์จริง ฝั่งผู้ใช้ต้องรายงานว่าไม่พบแชร์ แยกจากข้อผิดพลาดด้านสิทธิ์ และฝั่งผู้แชร์ต้องไม่แสดงแถวว่าง `Unknown`
- [ ] ใส่ระเบียนแชร์ว่าง `{}` ใน state ทดสอบ; เมื่อเปิดแท็บผู้แชร์ โปรแกรมลบเฉพาะระเบียนว่าง ไม่ลบรายการที่มีชื่อ/พาธ/ข้อมูลสิทธิ์ และปุ่มเริ่มแชร์แจ้งเมื่อยังไม่เลือกต้นทางหรือชื่อ
- [ ] ให้ SMB เชื่อมต่อได้แต่บัญชีผู้ใช้ถูก NTFS ปฏิเสธ; โปรแกรมต้องแสดงข้อผิดพลาดและชื่อบัญชีแทนการแจ้งว่าเปิด UNC สำเร็จ
- [ ] Map Drive ด้วยอักษรที่เลือกเองและ Auto; อักษรที่ใช้อยู่ต้องถูกปฏิเสธ
- [ ] เลือก reconnect แล้วออก/เข้าสู่ Windows ใหม่; ตรวจว่าไดรฟ์กลับมา
- [ ] เปิดไดรฟ์ที่ Map แล้ว ยกเลิก Map เฉพาะรายการของโปรแกรม และปฏิเสธการยกเลิกขณะมีไฟล์เปิด
- [ ] ทดสอบ error 1219 เมื่อมีการเชื่อมต่อเครื่องเดียวกันด้วยข้อมูลเข้าใช้อื่น
- [ ] บนเครื่องผู้ใช้ที่เคยต่อ `\\SCHOOL-HOST\Laptop` ด้วย WindowsCurrent เปลี่ยน UNC เป็น `\\SCHOOL-HOST\StudentJ2551` แล้วกดเปิด UNC และ Map Drive ตรวจว่าใช้บัญชีเดิมและอ่านแชร์ใหม่ได้โดยไม่ตัด connection อื่น
- [ ] บนเครื่อง `192.168.1.133` อัปเดตจาก v3.5 โดยไม่เลือก Set zero แล้วสลับแท็บผู้แชร์ เลือก `F:\` ที่มี junction ภายในและ `D:\` ที่ต้องสแกนนาน ตรวจว่าเริ่มแชร์ได้และไม่มี UAC เมื่อกดดูรายการ เริ่มแชร์ หยุดแชร์ หรือรีเฟรช หลังการติดตั้ง
- [ ] ปิดโปรแกรมและเปิดใหม่ในบัญชีเดิม ตรวจว่า Host Broker ยังทำงานและไม่ถาม UAC ซ้ำ; ลองบัญชี Windows อื่น ตรวจว่าไม่สามารถส่งคำขอสิทธิ์สูงผ่าน Broker ของบัญชีที่ติดตั้ง

## บูตและกู้คืน

- [ ] เลือกแชร์อัตโนมัติทุกชนิด แล้วรีสตาร์ตเครื่องผู้แชร์ ตรวจ UNC ก่อนล็อกอินและก่อนเปิด GUI
- [ ] เมื่อ LAN เดิมยังไม่พร้อมหลังบูต รายการรอโดยไม่เปิดแชร์; เมื่อวงเดิมกลับมาเป็น Public โปรแกรมตั้ง Private และเปิดแชร์เอง โดยไม่เปิดแชร์บนวงอื่น
- [ ] ปิด GUI แต่แชร์ยังทำงาน; ไฟล์เดียวที่บันทึกแบบแทนที่ยังซิงก์กลับ
- [ ] แชร์ไฟล์เดียวโดยปิด AutoStart แล้วปิด GUI; ก่อนรีบูตต้องยังซิงก์ และต้องหยุดเมื่อเปลี่ยนไปเครือข่ายอื่นที่ไม่ได้จดจำไว้
- [ ] ยกเลิก AutoStart สำหรับรายการหนึ่ง; หลังบูตไม่เปิดรายการนั้น
- [ ] กดหยุดแชร์; หลังบูตต้องไม่กลับมาเอง และ ACL ของรายการนั้นถูกย้อนคืนโดยไม่เปลี่ยน ACL อื่น
- [ ] ถอดไดรฟ์ออกหรือเปลี่ยนดิสก์ที่ใช้อักษรเดิม; ห้ามเปิดแชร์ข้อมูลจากดิสก์ใหม่
- [ ] เปลี่ยน LAN เดิมจาก Private เป็น Public ขณะใช้งาน; ตัวดูแลต้องตั้งกลับเป็น Private แล้วแชร์ต่อ ตรวจอีกครั้งเมื่อสลับไปเครือข่ายอื่นว่าแชร์ถูกหยุด
- [ ] ตรวจ Advanced sharing settings หลังเริ่มแชร์และถอนการติดตั้ง: Public, Network discovery, Public folder sharing และ 128-bit ไม่ถูกเปลี่ยน
- [ ] อัปเดตด้วย `Update-LanShare.ps1` ขณะมีรายการแชร์; รายการเดิมและค่า AutoStart อยู่ครบ และ Host Worker กลับมาทำงาน
- [ ] ถอนการติดตั้ง; งาน Scheduled Task, share, ACL และกฎไฟร์วอลล์ที่โปรแกรมสร้างถูกเก็บกวาด แต่ไฟล์ต้นฉบับอยู่ครบ

## Online รุ่น 3.71 — ตรวจบนสองเครือข่ายและเครื่องจริง

- [ ] ทำตาม docs/ONLINE-TH.md และลงทะเบียน 7 เครื่องด้วย One-off Setup Key แยกกัน
- [ ] ทั้ง VPN เชื่อมต่อแล้วและแชร์ Online เปิด; Console policy อนุญาต TCP445 จากกลุ่มครูไปผู้แชร์
- [ ] เปิด Protected share อ่าน/เขียนได้พร้อมกันจากครู 6 เครื่องอย่างน้อย 5 นาที ใช้ tests/Verify-OnlineRemote.ps1 เก็บ checksum, MB/s, P2P/Relay ของแต่ละเครื่อง
- [ ] ตัด/ต่ออินเทอร์เน็ต เปลี่ยน Wi-Fi Sleep/Wake และรีบูต; โปรแกรมไม่ส่งรหัสผ่านเมื่อยืนยันตัวตนปลายทางไม่ได้
- [ ] เปลี่ยน IP หรือกลุ่ม/บัญชี NetBird: หยุดเป้าหมายเดิม รับข้อมูลเข้าใช้ใหม่ก่อนเชื่อมอีกครั้ง
- [ ] เปิด Online บน Wi-Fi Public โดย NetworkCategory ไม่ถูกเปลี่ยน; กฎ LFS-NetBird-SMB จำกัด interface/local IP/approved peer IP เท่านั้น
- [ ] ปิด Online แล้วกฎรับ SMB Online ถูกปิด; LAN เดิมยังทำงานตามการตั้งค่า
